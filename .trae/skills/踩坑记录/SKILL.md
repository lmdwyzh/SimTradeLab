# 踩坑记录

记录 SimTradeLab 策略开发与回测过程中遇到的典型问题、根因和修复方法，便于后续快速排查。

## 1. get_history 返回空结果

- **现象**：`get_history(...)` 返回空 DataFrame，策略无交易。
- **常见根因**：
  - 数据路径指向了精简数据目录，股票数量不足；
  - `field` 传入的是逗号分隔字符串，但代码按单字段解析，导致字段匹配失败。
- **排查与修复**：
  - 先确认 `data_path` 下是否有目标股票完整数据；
  - 检查字段解析逻辑，字符串应拆分为列表后再查询。

## 2. 全股票池回测很慢

- **现象**：日线回测加载慢、卡顿。
- **常见根因**：未在 `before_trading_start` 中调用 `set_universe()`，系统仍按大量股票预加载。
- **排查与修复**：
  - 在盘前设置当日股票池；
  - 调用 `set_universe(g.stock_pool)` 缩小有效数据加载范围。

## 3. 策略候选股充足但仍 0 交易

- **现象**：日志里能看到候选股，但不下单。
- **常见根因**：
  - 下单前存在不当的存在性/持仓检查，把合法候选跳过了；
  - 资金检查或持仓上限检查逻辑有误。
- **排查与修复**：
  - 精简下单前判断，只保留必要约束；
  - 打印候选、资金、持仓状态后再下单。

## 4. 回测环境与依赖问题

- **现象**：运行报错、导入失败、类型注解不兼容。
- **常见根因**：
  - Poetry 环境 Python 版本与依赖不匹配；
  - 使用了非当前环境运行脚本。
- **排查与修复**：
  - 统一使用项目指定 Python 环境运行；
  - 必要时重建虚拟环境并重装依赖。

## 5. `data` 对象访问陷阱

- **现象**：在 `handle_data(context, data)` 中判断候选股票是否可交易时，策略 0 交易。
- **常见根因**：错误使用 `if security not in data` 做预检查。`Data` 对象是懒加载的，初始化时为空，`in` 检查会误伤所有候选。
- **排查与修复**：
  - 不要用 `in` 检查 `data` 对象成员资格；
  - 采用 EAFP：直接访问并用异常捕获真正的数据缺失。

```python
# ❌ 错误
if security not in data:
    continue
current_price = data[security]['close']

# ✅ 正确
try:
    current_price = data[security]['close']
except (KeyError, ValueError):
    continue
```
